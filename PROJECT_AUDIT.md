- **Authentication architecture** (all under `src/SAUDICO.Federate.ACC`, one focused type per concern, no multipurpose "ApsService"):
  - `Configuration/`: `ApsConfiguration`, `ApsConfigurationValidationResult`, `IApsConfigurationService`/`ApsConfigurationService` — loads `config/apssettings.json`, merges `config/apssettings.local.json` over it, rejects any `clientSecret` key, validates schemaVersion/Enabled/ClientId/loopback callback/https Autodesk-host endpoints/read-only scope allow-list.
  - `Pkce/`: `PkcePair`, `IPkceService`/`PkceService` — RFC 7636 verifier (32 random bytes, Base64URL, 43 chars) + S256 challenge, `RandomNumberGenerator`-backed state.
  - `OAuthState/`: `OAuthAuthorizationState`, `IOAuthStateStore`/`InMemoryOAuthStateStore` — single in-flight attempt, one-time consume, rejects wrong/replayed state.
  - `Callback/`: `OAuthCallbackResult`, `ILocalOAuthCallbackListener`/`LocalOAuthCallbackListener` — `HttpListener` on the exact configured loopback URI, cancellation + timeout support, safe static HTML response, parses code/state/error/error_description, stops/disposes on every exit path.
  - `Tokens/`: `ApsToken`, `IApsTokenStore`/`DpapiApsTokenStore` — persists only the refresh token via `ProtectedData.Protect(DataProtectionScope.CurrentUser)` to `%LOCALAPPDATA%\SAUDICO\Federate\Auth\aps-token.dat`, atomic temp-file + `File.Replace`, corrupt/undecryptable data returns null instead of throwing.
  - `Authentication/`: `ApsAuthenticationState`, `ApsAuthenticationStateChangedEventArgs`, `IApsAuthenticationService`/`ApsAuthenticationService` (orchestration only — delegates all HTTP/crypto/storage), `IApsAuthorizationClient`/`ApsAuthorizationClient` (authorize-URI + token-exchange + refresh, the one HTTP client for Authentication v2), `ISystemBrowserLauncher`/`SystemBrowserLauncher` (system browser via `Process.Start`, never embedded).
  - `Profile/`: `ApsUserProfile`, `IApsUserProfileService`/`ApsUserProfileService` — calls `/userinfo`, maps 401 to `ApsSessionExpiredException`.
  - `Http/`: `IApsHttpTransport`/`ApsHttpTransport` — the one shared safe HTTP transport (timeout, User-Agent, JSON error parsing into `ApsApiException` without ever surfacing raw response bodies).
  - `Errors/`: `ApsApiException`, `ApsConfigurationException`, `ApsAuthenticationException` (carries a `ApsAuthenticationFailureReason`), `ApsAuthorizationDeniedException` (derives from it), `ApsSessionExpiredException`.
- **Sign-in flow**: implements the exact 16-step sequence (validate config → PKCE → state → start callback listener before browser launch → build authorize URI → launch system browser → await callback → validate state → handle denial/error → exchange code+verifier → validate response → compute `ExpiresAtUtc` → store access token in memory → DPAPI-persist refresh token → fetch `/userinfo` → raise state-changed event). No client secret anywhere. `client_id` sent in the token-exchange form body per the public/PKCE client contract (verified against `aps-sdk-net`'s `TokenApi.gen.cs`).
- **Token refresh/`GetValidAccessTokenAsync`**: safety-margin-based early return for a still-valid token; `SemaphoreSlim`-serialized refresh so concurrent callers produce exactly one HTTP refresh call (unit-tested with 5 concurrent callers); rotated refresh token is persisted every time; `invalid_grant` clears the stored token and DPAPI file and moves to `SignedOut`; never returns an expired token.
- **DPAPI behavior**: `DataProtectionScope.CurrentUser` — undecryptable by another Windows account; only the refresh token is ever written to disk, access token is memory-only for the process lifetime; corrupt file → safe `null` (forces fresh sign-in), never throws into the caller; `SignOutAsync` deletes the file (best-effort revocation with Autodesk was deliberately NOT implemented — no verified, documented public revoke endpoint was found for Authentication v2, so nothing was invented; local logout always completes even if Autodesk is unreachable).
- **User profile**: `sub`→`UserId`, `name`/`preferred_username`→`DisplayName`, optional `email`/`picture`. Not written to the CSV report. Does not influence any ACC permission decision (none exist yet).
- **UI status**: `AuthPanel.xaml`/`AuthPanel.xaml.cs` (code-behind has zero auth logic — only `DataContext = new AuthViewModel(...)`) + `AuthViewModel.cs` (`INotifyPropertyChanged`, 4 `RelayCommand`s: SignIn/SignOut/Cancel/Retry, dispatcher-marshaled state updates) + `RelayCommand.cs`. ## Architecture summary
Multi-project .NET solution: `Shared` (enums/constants) ← `Core` (models, settings, model-kind detection, document open, source-integrity validator) ← `Export` (view prep + NWC export + CSV report + structured logging) ← `UI` (WPF `Manager` window, now also hosting the isolated `AuthPanel`/`AuthViewModel`) ← `Revit2024`/`Revit2025` (thin Revit host add-ins, identical logic, differing only by TFM/`AssemblyName` via `Directory.Build.props` conditionals). `SAUDICO.Federate.ACC` sits beside `Core`/`Export` — it depends only on `Shared`-independent code and `Logging`, and is depended on by `UI` (never by `Export` or the Revit hosts directly, and never referencing Revit APIs itself). `Logging` (Serilog) is referenced by `Export`, `ACC`, and both hosts. Revit API calls are marshaled onto the valid API context via `IExternalEventHandler`/`ExternalEvent` (FIFO queue), matching CLAUDE.md's execution-context rule. `Directory.Build.props` sets `CopyLocalLockFileAssemblies=true` globally so non-WPF projects physically ship their NuGet dependencies (Serilog, DPAPI package) into the final add-in output; the WPF host projects instead resolve some of those (e.g. `ProtectedData`) from the shared framework — see the packaging note above.
